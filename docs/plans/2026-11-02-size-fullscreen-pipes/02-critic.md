# 1라운드 — 검증가 (brainstorm-critic)

## 코드로 확인한 사실
| # | 사실 |
| --- | --- |
| F1 | 세로 화면은 필드 폭에 맞춰 이미 벽에서 벽까지 꽉 참(여유 0.5%) → 최신 세로폰에 좌우 여백 없음 |
| F2 | 위아래는 HUD 84px + 스킬 140px + 안전영역 — 390×844 기준 약 305px, 화면의 36%(추정) |
| F3 | 높이가 모자란 화면(16:9, iPad 세로)에서만 좌우 여백 |

| F5 | 공끼리 충돌 없음 → 관이 막히진 않지만 공이 많으면 일정 비율 필터 |
| F6 | 공이 박스 안 판정 즉시 'enter' 축하(토스트·0.5배 슬로모 0.3초·햅틱) |
| F7 | 시뮬이 가변 프레임 dt → 모서리 반전이 주사율에 따라 달라질 수 있음 |
| F8 | 기믹은 월드당 하나, 해류는 공을 되돌리지 못함 |
| F9 | 슬로모 기반(pacing.slowMo) 이미 있음 |
| F10 | 받아쳐도 공이 늘지 않음, 서브 3개 → 긴장은 첫 진입~첫 과일 구간 |
| F11 | 가로 화면 허용(iOS 가로 2방향, Android 미고정) |

화면별 여백(추정 ±15%): 390×844 좌우 0·위 빈 띠 ~30px+HUD · 360×780 좌우 0·위 ~85px+HUD · 360×640 좌우 각 ~20px · 768×1024 좌우 각 ~90px.

## 공통 리스크
①과 ②가 같은 레버(COLS 축소) · A2와 C1을 함께 내면 원인 분리 불가 · 가변 dt · 출시 직후 회귀 위험(1.0.1과 분리) · 스테이지별 첫 과일 시간 기준선 부재.

제안 순서: 0) 스크린샷+기기별 여백 출력 → 1.0.1 게임플레이 변경 없음 → 1.1 A2 → 1.2 C1+C4(10~59) → 1.3 C2.
